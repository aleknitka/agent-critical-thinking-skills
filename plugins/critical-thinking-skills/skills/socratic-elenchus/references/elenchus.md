# Socratic Elenchus — Method

From Socratic elenchus → Paul & Elder (2006) elements of thought (*concepts*) → Ennis (1996).

## Four steps

1. **Elicit a definition** that states necessary and sufficient conditions — not examples, synonyms, or slogans.
2. **Counterexample:** one case that satisfies the definition but should not count (over-inclusive) or fails it but should (under-inclusive). Boundary cases are the test — central cases hide vagueness.
3. **Revise** to handle the counterexample, keeping one sentence. One revision; a second only if the first creates a new counterexample.
4. **Operationalize:** a measurement or decision rule. "Would two judges agree on cases A/B using this rule?" If not, the concept is still vague.

## Techniques

- Counterexample, thought experiment, boundary case, necessary/sufficient split, genus + differentia.
- Ask: "What would count as *not* X?" and "What does X exclude?"

## Worked example 1 — "engagement"

- Term: engagement.
- Initial: "users like the product".
- Counterexample: a user who likes the product but never opens it (satisfies "like" via survey but not engagement); a user who opens daily angrily (engaged but does not "like").
- Revised: "a user engages when they complete a value-creating action within the product in a session".
- Operational: count sessions with ≥1 value action; threshold e.g. ≥3 such sessions in 7 days.

## Worked example 2 — "quality"

- Term: quality advice.
- Initial: "good advice".
- Counterexample: advice that feels good but leads to a bad bet; advice that feels harsh but prevents loss.
- Revised: "advice that, if followed, raises the expected value of the decision that hangs on it".
- Operational: pre-commit the decision threshold; score whether following the advice moves the posterior past it.
